# Zaruku: месячная AI-видимость и конкуренты

## Цель

Добавить в Zaruku отдельную вкладку «ИИ-видимость и конкуренты», которая показывает ручные месячные снимки из раздела «Видимость сайта в Алисе AI» Яндекс Вебмастера. Вкладка должна хранить и показывать официальный Share of Voice за месяц, запросы из выгрузки, присутствие и позицию Zaruku, страницы Zaruku, источники Алисы и конкурентные домены.

В SEO остаётся только краткий показатель последнего месяца и переход к полной вкладке.

## Подтверждённый источник за август 2026

- Период: `2026-08`.
- Официальная доля запросов из интерфейса Яндекс Вебмастера: `43,91%`.
- Файл: `neurostatistics-zaruku.ru-20260904-152814 (1).xlsx`.
- Дата получения файла: `2026-09-04 15:28` по имени выгрузки.
- В файле 155 запросов.
- Для 89 запросов поле «Присутствует сайт» равно `true`.
- Доля присутствия внутри выгруженных примеров: `89 / 155 = 57,42%`.
- В каждой строке есть запрос, ссылка на ответ Алисы и до десяти страниц-источников.
- Всего в строках сохранено 1 313 ссылок-источников.
- Во всех 89 запросах с точным доменом `zaruku.ru` портал стоит на первом месте среди перечисленных источников.

Официальные `43,91%` и рассчитанные по выгрузке `57,42%` — разные показатели. Официальная доля относится к полному набору запросов, который использует Яндекс. Файл содержит набор примеров и не является знаменателем официального Share of Voice. В интерфейсе эти показатели всегда подписываются отдельно.

## Варианты и решение

### Выбранный вариант: нормализованные месячные снимки

Итог месяца, запросы, источники и отмеченные Яндексом сайты хранятся в отдельных связанных таблицах. Это позволяет строить историю, фильтровать запросы, считать позиции и конкурентов без чтения Excel во время открытия дашборда.

### Не выбранные варианты

- Хранить только Excel или JSON целиком: проще загрузить, но нельзя надёжно фильтровать и сравнивать данные.
- Расширить существующую `seo_ai_visibility`: таблица рассчитана на итоговые числа и не хранит запросы и источники.
- Использовать устаревшую `seo_ai_visibility_weekly`: таблица помечена как неиспользуемая и имеет неподходящую недельную структуру.

## Границы задачи

В задачу входят:

- новая вкладка Zaruku;
- краткая SEO-карточка;
- новые канонические таблицы MySQL;
- ручная команда импорта Excel;
- загрузка августовского снимка;
- перенос июльской контрольной точки в новый месячный ряд;
- проверки, тесты, миграция, публикация и рабочая проверка.

В задачу не входят:

- недокументированные внутренние методы Яндекса;
- автоматизация браузера Яндекс Вебмастера;
- автоматическое расписание импорта;
- изменение источника обычных показов, кликов и позиций Яндекс Вебмастера;
- медицинская классификация запросов внутри этой вкладки.

## Хранение данных

### 1. `canonical_alice_visibility_snapshots`

Одна строка соответствует одной полученной версии месячного снимка.

Основные поля:

- `id` — внутренний идентификатор снимка;
- `source_key` — `yandex_webmaster_alice_manual`;
- `analytics_account_id` — `66624469` для Zaruku;
- `domain` — `zaruku.ru`;
- `period_month` — первый день месяца, например `2026-08-01`;
- `captured_at` — дата и время получения выгрузки;
- `official_sov_pct` — официальный показатель из интерфейса Вебмастера;
- `exported_query_count` — количество запросов в файле;
- `portal_present_query_count` — количество запросов с присутствием Zaruku;
- `sample_presence_pct` — рассчитанная доля присутствия в примерах;
- `source_filename` — имя переданного файла без пути;
- `source_sha256` — контрольная сумма файла;
- `publication_status` — `published` или `superseded`;
- `supersedes_snapshot_id` — ссылка на явно заменённую версию;
- `ingestion_run_id` — идентификатор ручной загрузки;
- `source_payload_json` — компактные исходные примечания и унаследованные показатели, но не замена нормализованным полям;
- `created_at`, `updated_at`.

Одинаковая контрольная сумма для того же источника загружается повторно без создания дубля. Изменённый файл для уже опубликованного месяца по умолчанию отклоняется. Для исправления владелец должен явно указать заменяемый снимок; старая версия остаётся в базе со статусом `superseded` и доступна для аудита.

### 2. `canonical_alice_visibility_queries`

Одна строка соответствует одному запросу внутри конкретного снимка.

Поля:

- `snapshot_id`;
- `query_hash` и полный `query_text`;
- `portal_present`;
- `portal_position` — первое место точного домена `zaruku.ru` среди источников 1–10;
- `portal_url` — страница Zaruku, если она присутствует;
- `alice_answer_url`;
- `source_count`;
- `raw_present_value` — исходное значение из файла для проверки;
- `created_at`.

Уникальность: `snapshot_id + query_hash`.

### 3. `canonical_alice_visibility_sources`

Одна строка соответствует одному источнику Алисы для одного запроса.

Поля:

- `query_id`;
- `source_rank` от 1 до 10;
- `source_url`;
- `source_domain` в нормализованном виде;
- `is_portal` — точный домен Zaruku или его поддомен;
- `created_at`.

Уникальность: `query_id + source_rank`. Все страницы сохраняются, даже если один домен встречается несколько раз.

### 4. `canonical_alice_visibility_featured_sites`

Хранит список «Случайные примеры сайтов с большим числом упоминаний», который Яндекс показывает отдельно от выгрузки запросов.

Поля:

- `snapshot_id`;
- `display_order`;
- `site_url`;
- `site_domain`;
- `list_kind` — `yandex_random_high_mentions`;
- `created_at`.

Список не получает искусственный рейтинг и не смешивается с частотой доменов, рассчитанной по 155 строкам Excel.

## Перенос июля

Текущая строка `seo_ai_visibility` за `2026-07` остаётся неизменной. В новую таблицу снимков добавляется отдельная июльская запись:

- `official_sov_pct = 44,00`;
- источник — `wm_alisa_manual_legacy`;
- `exported_query_count`, `portal_present_query_count` и `sample_presence_pct` остаются пустыми, потому что исходная детализация не сохранена;
- прежние значения `mentions = 89` и `citations = 155` сохраняются в `source_payload_json` с пометкой «определение не подтверждено» и не показываются как количество запросов или цитат.

Так июль остаётся видимым на графике, а старые числа не получают нового неподтверждённого смысла.

## Ручной импорт

Команда импорта принимает:

- путь к Excel;
- месяц;
- официальный Share of Voice;
- время получения выгрузки;
- список отмеченных Яндексом сайтов;
- режим проверки или выполнения;
- явный идентификатор заменяемого снимка, если выполняется исправление.

Последовательность:

1. Прочитать Excel и проверить заголовки `Запрос`, `Присутствует сайт`, `Ответ в Алисе AI`, `Сайт 1`–`Сайт 10`.
2. Проверить непустые запросы и отсутствие повторов.
3. Нормализовать булево значение присутствия.
4. Проверить ссылки и выделить точный домен Zaruku, не используя простое вхождение строки `zaruku.ru` в чужой URL.
5. Рассчитать позицию Zaruku и количество источников.
6. Сверить рассчитанное присутствие с полем выгрузки. Любое расхождение останавливает публикацию.
7. Рассчитать `sample_presence_pct` и сохранить официальный процент отдельно.
8. Проверить контрольную сумму и политику повторной загрузки.
9. В одной транзакции записать снимок, запросы, источники и отмеченные сайты.
10. После записи повторно сверить количество запросов, присутствий и источников.

Excel не копируется в публичные файлы приложения. В базе сохраняются только нормализованные данные, имя файла, контрольная сумма и короткие примечания.

## Read model

Дашборд читает только канонические таблицы MySQL. Компоненты браузера не читают Excel и не обращаются к Яндексу.

Read model возвращает:

- список опубликованных месяцев и версий;
- официальный SoV и изменение в процентных пунктах к предыдущему опубликованному месяцу;
- покрытие выгрузки;
- запросы с позицией и страницей Zaruku;
- все источники каждого запроса;
- частоту конкурентных доменов;
- список отмеченных Яндексом сайтов;
- источник, время получения и статус снимка.

Частота конкурента считается как количество разных запросов, где домен присутствует хотя бы один раз. Zaruku и ссылка на ответ Яндекса исключаются. Повторные страницы одного домена в одном запросе не увеличивают счётчик.

## Интерфейс

### Навигация

Новая вкладка «ИИ-видимость и конкуренты» располагается после «SEO» и перед «Спрос Wordstat». У неё собственный выбор месяца, поэтому общий недельный переключатель SEO OS на неё не влияет.

### Краткая карточка в SEO

Карточка показывает:

- последний опубликованный месяц;
- официальный Share of Voice;
- изменение к предыдущему месяцу в процентных пунктах;
- пометку «ручная выгрузка»;
- переход «Открыть запросы и конкурентов».

Старая развёрнутая панель AI-видимости в SEO удаляется, чтобы не дублировать новую вкладку.

### Верх новой вкладки

- выбор месяца;
- график официального Share of Voice по месяцам;
- карточка «Доля запросов в Алисе AI»;
- карточка «Запросов в выгрузке»;
- карточка «Zaruku присутствует»;
- карточка «Доля в примерах».

Под карточками показывается простое пояснение, почему официальный процент и доля внутри примеров отличаются.

### Запросы и позиция Zaruku

Таблица содержит:

- запрос;
- присутствие Zaruku: «Есть» или «Нет»;
- место Zaruku среди источников;
- страницу Zaruku;
- первые три конкурентных источника;
- ссылку «Открыть ответ Алисы»;
- раскрытие полного списка до десяти источников.

Доступны поиск, фильтр по присутствию и постраничный просмотр. Для июля таблица показывает понятное сообщение, что детализация не была сохранена.

### Конкуренты

Первый блок показывает домены, фактически встречающиеся в выгрузке, и количество запросов с каждым доменом. Второй блок показывает переданные Яндексом случайные примеры заметных сайтов без места и без утверждения, что порядок означает рейтинг.

Для августа второй блок содержит:

2. `chernyakhovsk39.ru`
3. `yusupovs.com`
4. `dzen.ru`
5. `doctu.ru`
6. `brobank.ru`
7. `zoon.ru`
8. `amse.spb.ru`
9. `oncology-centr.ru`
10. `2gis.ru`

## Состояния и ошибки

- Нет снимков: вкладка объясняет, какие данные нужно передать для первой загрузки.
- Есть итог месяца, но нет Excel: график и официальный процент доступны, таблица запросов показывает отсутствие детализации.
- Excel не проходит проверку: данные не публикуются, импорт сообщает конкретную строку и причину.
- Файл уже загружен: команда сообщает, что снимок уже существует, и ничего не меняет.
- Для месяца передан другой файл: команда требует явного подтверждения замены.
- Отдельная таблица недоступна: read model возвращает частичный статус; доступные месячные итоги остаются видимыми.

## Проверки

- Парсер читает 13 ожидаемых колонок и не зависит от ошибочного `dimension ref="A1"` в исходном Excel.
- На августовском файле подтверждаются 155 запросов и 89 значений `true`.
- Официальные 43,91% не пересчитываются из 89/155.
- Позиция определяется только по точному домену Zaruku.
- Один конкурентный домен считается не более одного раза на запрос.
- Повторная загрузка того же файла не создаёт дублей.
- Замена месяца без явного разрешения отклоняется.
- Июльские 44,00% остаются видимыми после перехода на новые таблицы.
- SEO показывает только краткую карточку, а новая вкладка — всю детализацию.
- Проверяются пустые, частичные и ошибочные состояния.
- Перед публикацией выполняются тесты, типизация, сборка, миграционная проверка и рабочая проверка дашборда.

## Критерии приёмки

- В Zaruku есть вкладка «ИИ-видимость и конкуренты».
- В SEO осталась только краткая карточка AI-видимости.
- На графике видны июль `44,00%` и август `43,91%`.
- Август показывает 155 запросов, 89 присутствий и отдельные 57,42% по примерам.
- Можно найти запрос, увидеть место и страницу Zaruku и раскрыть все источники.
- Конкуренты рассчитаны по выгрузке и отделены от случайных примеров Яндекса.
- Данные читаются из канонической MySQL, а не из Excel или внешнего API во время открытия дашборда.
- Повторные месячные загрузки сохраняют историю и не меняют старые данные без явного подтверждения владельца.
